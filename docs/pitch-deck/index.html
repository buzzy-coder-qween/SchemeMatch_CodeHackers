01 — Innovation Originality · Differentiation · Relevance

A transparent eligibility engine, not another scheme search box.

Citizens get a ranked answer to “which schemes fit me, and why” — computed from statutory rules, with the reasoning and the missing paperwork exposed.

“Why it fits” in plain language
STEP 5
Gap detection
Flags missing documents before applying
Differentiator

Deterministic, auditable rules

Every match is a reproducible function of 22 statutory rule sets — no hallucinated eligibility, no black-box ranking.

Differentiator

AI assists, it does not decide

Gemini only parses free text into a profile. The score itself is rule-based, and the app works fully with no API key.

Differentiator

Explains the “no” too

Ineligible schemes state which gate failed, so citizens learn the criteria instead of guessing.

02 — Impact Importance of the problem · Credible benefit

Eligible people miss benefits because the rules are invisible.

Welfare information is spread across departmental portals, written in bureaucratic language, and gated by criteria that are never surfaced to the person who qualifies.

The problem

Discovery is the bottleneck, not intent

A student, a 2-acre farmer, and a woman head of household qualify for different schemes from the same portal — and none of them can tell which without reading every rule.

Who benefits

Six citizen personas modelled end to end

College student, small farmer, homemaker and head of family, unemployed graduate, senior citizen, micro-entrepreneur — each with a one-click demo profile.

Access

Kannada, Hindi, and voice

Full trilingual UI plus speech input and read-aloud output, so low-literacy and first-time internet users are not excluded by the interface.

Credible benefit

Fewer rejected applications

Document-gap detection surfaces Aadhaar–NPCI seeding, Nadakacheri RD certificates and land records before submission — the failure points that send citizens back to the counter.

03 — Execution Implementation depth · Testing · Build quality

Built, tested, and deployed in one repository.

A typed React client, an Express API, a 22-scheme rule engine and a real deployment pipeline — verified end to end, not mocked.

  • Rule engine — hard gates, weighted affinity scoring (0–100), gap detection and Markdown report generation in matchingEngine.ts.
  • Bilingual extractor — regex/keyword parser handling Kannada and Devanagari numerals, used as the deterministic fallback behind Gemini.
  • Hardened AI path — 15 s extraction and 20 s chat timeouts with graceful fallback, so a stalled model can never hang the UI.
  • 18 automated tests across matching, extraction and speech, run on the Node test runner.
  • Deployment-ready — honours injected PORT, serves built assets with SPA fallback in production.

06 — Feasibility Practicality · Deployment · Constraints · Viability

Deployable today on a free tier, with a clear path to scale.

Static hosting for the rule engine now; a Node web service when AI endpoints are enabled. No proprietary infrastructure, no vendor lock-in.

Deployment

Two supported paths

Static — publish dist, rule engine runs in the browser.
Web service — Express + Vite build, AI routes live, health check at /api/health.

Cost

Free tier viable

Render free instance, zero database, Gemini billed only per AI call — and the app degrades to zero-cost deterministic behaviour without a key.

Constraints, stated plainly

What it does not do yet

  • No accounts or saved profiles — state is per session.
  • No application submission; it links to Seva Sindhu and myScheme.
  • Scheme rules are a curated snapshot and must be maintained.
Trust

Verification is built in

Every recommendation and report carries the statutory disclaimer that approval is not guaranteed and official portals remain the source of truth.

Roadmap

Maintenance

Data stays out of the components
